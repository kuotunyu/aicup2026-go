## 經過和揭露

- 判定只做一次；smoke 用雜訊特徵、縮成 2 個 epoch 的排程（只確認程式和時間）。
- 訓練前由另一個代理獨立審查程式（只看程式和 smoke 的接縫紀錄）：沒有 blocker，6 個 minor 已處理 5 個（PLAN 第 10 節）。
- inner 已被 P1、08、09、prereg12、15–25 重複使用，選擇偏差約 0.003；這次的差本來就小於這個量級。
- 用了驗證玩家的棋訓練翻譯模型（只在這次探索；沒採用，不影響 25）。
- 和交辦的差異：沒有。範圍照 PLAN 第 2 節：只換 P1TO 項；SET 項（S25）繼續用 Q09 map 的 μ、σ（S25 是用它訓練的），所以 Q26 和 Q25 的 SET 項逐位元相同；EX 只是 lowrank3_ex 的輸入，不是融合項。
- 程式修正（訓練前）：`p25_lib.loaded_repo_modules` 會把 torch 的 `_classes.py`／`_ops.py`（相對路徑的 `__file__`）算成 repo 檔，`p26_lib` 改成只收絕對路徑（p25_lib 凍結，不改）。
- 一個可以考慮、但這次沒做的方向（只記錄）：翻譯模型和 set 模型都吃 P1 特徵，資訊重疊；若要再往 P1 這條線加分，應該在 set 模型那一側（題目層級）想辦法，不是逐盤模型。
