# prereg32 試跑（第 0 階段）：set 模型的 weight decay × 訓練長度（競賽二，只看留出 NLL，不碰 inner）

2026-11-10 寫成，**在跑出任何數字之前 commit**。主 session 交辦（使用者 11/10 要求檢討「長期訓練、Warmup、Cosine Annealing、Weight Decay」並同意照建議做）。這是試跑：只決定「值不值得另寫第 1 階段的 PLAN」，不寫 `docs/PREREG_32`、不做測試日工具、不上傳、不讀任何 inner 資料。不碰驗證集答案的資料夾、不跑 `tools/score.py`。全部 CPU，不用 4090。

## 0. 白話版

- 現在的 set 模型（S25）已經有 Warmup＋Cosine（OneCycleLR，前 10% 升溫、之後餘弦降到接近 0）和 AdamW，但 weight decay 只有 0.01、訓練 15,000 步：AdamW 每一步把權重縮小 lr × wd，整段訓練加起來縮不到 8%，**等於沒有正則化**。
- 已 commit 的訓練紀錄顯示它在過擬合：訓練 batch 的損失約 0.65，留出玩家的 NLL 約 1.01；留出 NLL 在第 6,500～11,000 步最低，之後反而升高約 0.015（prereg25／29 `train_record.json` 的 curve）。
- 所以要試的是：把 weight decay 加大到真的有作用的量（0.1、0.3、1.0），以及把訓練拉長（4 倍、10 倍；文獻上的「頓悟」要靠大的 weight decay＋很長的訓練），看留出 NLL 會不會明顯變低。
- **先講預期：偏保守。** 玩家只有 6,619 位，過擬合多半是「記住玩家」，weight decay 能救的通常只有 0.005–0.02。門檻設在 −0.020，沒到就收掉。CPU 一個晚上跑完。

## 1. 做法（只差 wd、步數；其他全部照 S25，直接 import 不複製）

- 資料列、標準化、玩家角色（A 6,619／H 748）、留出題組、模型架構、lr 1e-3、OneCycle pct 0.1、batch 128、n ∈ {5,10,15,20}、dropout、種子規則（`torch.manual_seed(s)`、`default_rng([19, s])`）都照 S25（`p25_train.Rows`、`p19_train.train_seed`）。**不加 HD**（和 prereg31 分開，結果才分得清）。
- wd 用 context manager 暫時設 `p19_lib.WD`（`train_seed` 在呼叫當下才讀）；步數和 `eval_every` 是 `train_seed` 的參數。每個設定都取 **30 個檢查點**（`eval_every`＝步數／30），和對照的檢查點數相同，「取最小」的樂觀程度才一樣。
- 設定（每個都跑種子 0 和 1），照這個順序：

| 代號 | 步數 | wd | 每次約（8 執行緒時；4 執行緒會慢一些） |
|---|---|---|---|
| E1 | 15,000 | 0.1 | 9 分 |
| E2 | 15,000 | 0.3 | 9 分 |
| E3 | 15,000 | 1.0 | 9 分 |
| E4 | 60,000 | 0.1 | 36 分 |
| E5 | 60,000 | 0.3 | 36 分 |
| E6 | 150,000 | 0.3 | 89 分 |

- **執行緒**：排程 session 11/10 決定這個試跑用 **4 個 torch 執行緒**（暫時設 `p19_lib.THREADS`＝4；S25 的登記值是 8）。執行緒數會改變浮點加總順序，所以不能和 8 執行緒的紀錄逐位元比。
- **對照**＝同樣 4 執行緒、wd 0.01、15,000 步、30 個檢查點，種子 0 和 1 **在這個試跑裡最先重跑**（代號 E0，多 2 次訓練）。
- **接縫 R（只記錄＋健全性）**：E0 兩個種子的最佳留出 NLL 和 prereg25 `train_record.json` 已 commit 的 8 執行緒值相差必須都在 0.02 以內（超過表示管線有錯 → 停）；實際差值記錄下來。
- 每次訓練寫 `data/prereg32/run_{代號}_seed{s}.json`（curve、最佳步、最後一步的 NLL、秒數）和模型檔（不進 git）；完成的不重跑（`--resume`）；每次訓練之間看 `data/prereg32/STOP`。

## 2. 判定（已完成設定的純函式，判一次）

- 每個設定的 Δ＝兩個種子「最佳留出 NLL」的平均 − 對照（E0）同兩個種子的平均。
- **GO**：存在一個設定，Δ ≤ **−0.020**，而且兩個種子各自都比同種子對照低至少 0.010。有多個就取 Δ 最小的那一個當第 1 階段的候選（另寫 PLAN：多種子、放進 Q25 的 SET 項、inner 判一次）。
- **NO-GO**：其他情形。收掉，25 照舊。
- 門檻的來由：6 個設定在同一批留出題上挑（選擇偏差）；種子間標準差 0.003–0.005；prereg24 的對照顯示留出 NLL −0.022 只對應 S 項分數 +0.0034。
- 時間界限：11/11 08:00（或主 session 要開始 4090 工作時）還沒跑完就 STOP，**只用已完成的設定判定**，沒跑的寫明沒跑；不再續跑。
- 只記錄：每個設定最後一步的 NLL、最佳步的位置、最後一步訓練 batch 損失（過擬合差距）、每種盤數的留出 NLL。
