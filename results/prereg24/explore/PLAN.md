## 0. 白話版

- 19 的 set 模型 S19 只用了 probe 的 270,000 盤（5,767 位 fit 玩家）訓練。官方訓練集有 100 萬盤；扣掉驗證玩家和 inner 玩家，fit 玩家共有 720,307 盤，所以還有 **450,307 盤**沒算過 KataGo 特徵（第 1 節盤點）。
- 想問：多給 S19 這些盤，會不會更準？要算完它們的 P1 特徵要 4090 約 **20 小時**（只算訓練用的 A 玩家）。花之前先用 CPU 便宜地看「資料變少時 S19 退多少」：如果從一半資料到全部資料幾乎沒有進步，再加 1.5 倍資料多半也沒用（NO-GO）；如果還在明顯進步，就值得花 GPU（GO）。
- **盤點最重要的發現**：多出來的 450,307 盤**全部屬於已經在 probe 裡的玩家**（0 位新玩家），而且集中在 2,504 位盤數多的玩家（每人中位數 111 盤）。所以加資料是「同一批人每人更多盤」，不是「更多人」。因此小實驗除了交辦要的「玩家數」軸，另加一條和實際加資料最像的「每人盤數」軸，**GO／NO-GO 以後者判**（第 3 節說明為什麼）。

## 2. 小實驗（CPU，只用 probe 的 A／H 玩家）

### 2.1 不變的東西（照抄 S19）

- 架構、抽題、batch 128、15,000 步、OneCycle、AdamW、每 500 步在留出題組算 NLL 選步、numpy float64 前向：**全部直接 import `results/prereg19/explore/p19_train.py` 和 `p19_lib.py` 的函式**（`torch_model`、`train_seed`、`port_check`、`ProbeOnly`、`probe_colours`、`standardised_probe`、`sample_batch`、`holdout_set`、`set_logp_np`、`lse_mean`），不複製、不改。
- 玩家角色：S19 的 A／H（鹽 `c10-prereg19|holdout|`）。H 不變，所以**留出題組就是 S19 自己的那一組**（`holdout_set(pool_H, 100, 19019)`，最多 4,000 題），每個子集都在同一組題上選步和評估。
- 種子：和 S19 一樣 0、1、2（3 個），抽題亂數 `default_rng([19, 種子])`；`torch.set_num_threads(8)`。inner、驗證資料一律不讀。

### 2.2 子集（巢狀，事前寫死）

**P 軸（交辦要的：A 玩家的比例）**：u＝`int(sha256("c10-prereg24|players|<rank>:<player_id>")[:8], 16) % 4`。
- P25＝A 中 u＝0 的玩家的全部 probe 盤；P50＝u ∈ {0, 1}；P100＝全部 A。P25 ⊂ P50 ⊂ P100。

**R 軸（另加：每人盤數，模仿實際加資料）**：A 的全部玩家，只留 probe 的前幾批輪流抽樣。
- R11＝A 玩家在 P1 的盤（約 11%）；R56＝P1＋P2（約 56%）；R100＝P1＋P2＋P3＝P100。R11 ⊂ R56 ⊂ R100。
- 為什麼這條最像：probe 每一批都是「每位玩家輪流再抽一盤」，所以 R11→R56→R100 就是「輪流抽樣多跑幾圈，每人盤數上限逐步提高」；extra 正是「把同樣的輪流抽樣跑到底」（同一批玩家、盤數多的人得到最多）。P 軸減少的是玩家數，而 extra 一位新玩家都沒有。

**100% 那一點共用**：P100＝R100＝S19 本身。用凍結的 `results/prereg19/rank/s19_seed{0,1,2}.npz`（SHA 須等於 `results/prereg19/explore/train_record.json` 的 `models_sha256`），**不重訓**；另以接縫 R 確認「本實驗的程式重訓 100% 會得到 S19」。

每個子集：3 個種子 × 15,000 步。4 個子集（P25、P50、R11、R56）共 12 次，加接縫 R 的 1 次，每次約 15 分鐘（S19 實測 3 個種子 46 分鐘），兩個程序並行約 2 小時。

### 2.3 評估（每個子集一個數）

- 在 S19 的留出題組上：3 個種子的 lp 用 `lse_mean` 集成 → softmax → 規則 B（`p02_rank_fuse.rule_b_np`）→ 官方計分（1／e^-1／0）→ **分等級平均**（每級 400 題的平均，再對 10 級平均）＝S。
- 只記錄：集成的留出 NLL、每個種子單獨的 S 和 NLL、依盤數（5／10／15／20）的 S、依等級的 S、相鄰子集的配對差的題目 bootstrap 95% 區間（每級內重抽題，1,000 次，`default_rng(24)`）、選到的步數、訓練秒數、合格玩家數、移植核對最大差。
- 寫明的偏差：留出題組同時用來選步（S19 的規則），所以 S 略為樂觀；每個子集都一樣，比較的是差。

### 2.4 接縫（先過，否則停）

1. **接縫 F**：3 個凍結 S19 模型檔 SHA 等於 prereg19 `train_record.json`。
2. **接縫 H**：本實驗重建的 H 玩家數、留出題組題數等於 prereg19 `train_record.json` 的 `players`（H_players、holdout_questions）；凍結 S19 各種子在留出題組上的 numpy NLL，和 `best_holdout_nll`（torch float32）相差 ≤ 1e-4。
3. **接縫 P**：`probe_X.npy` 的 SHA 等於 09 的 `check_report.json`。
4. **接縫 R**：用本實驗的程式在 P100 重訓種子 0（15,000 步），得到的權重和 `s19_seed0.npz` 逐位元相同（10/20 與 11/5 兩次都看到這台機器的 CPU torch 可重現）。不相同時：**改用重訓的 P100 三個種子當 100% 那一點**（再訓練 2 個種子），報告寫明；不准挑比較好看的那一個。
5. 巢狀：P25 ⊂ P50 ⊂ A、R11 ⊂ R56 ⊂ R100 的盤（列號）核對；子集都只含 A 玩家。

## 3. GO／NO-GO（寫死，只判一次）

**GO 當且僅當 R 軸同時滿足**：
- (a) S(R100) − S(R56) ≥ **X＝+0.004**；
- (b) 單調：S(R11) < S(R56) < S(R100)。

**為什麼 X＝0.004**（看結果之前定的）：
- **雜訊**：融合後單一種子 set 模型的分數差，在 prereg19 是 +0.0185／+0.0223／+0.0196（標準差 0.0020），prereg23 是 5 個種子標準差 0.0021。3 個種子集成的標準差約 0.0020／√3＝0.0012，兩個獨立集成相減約 0.0017（題目是同一組、配對，題目抽樣雜訊大部分抵消）。X＝0.004 約 2.4 倍標準差：資料其實沒用時，單看 (a) 誤判 GO 的機率約 1%，加上 (b) 更低。
- **值不值得**：R56→R100 是盤數 ×1.8（0.85 次「加倍」）；extra 會讓 A 的盤數從約 243,000 變成約 650,000（×2.67，1.42 次加倍）。照「每加倍一次進步一樣多」外推，(a) 剛好成立時 S24 單獨約 +0.004 × 1.42／0.85 ≈ **+0.0067**，和下面 G1 的門檻 +0.005 同一個量級。小於 0.004 時外推不到 G1，花 20 小時 GPU 和 4 天時程不划算。
- 這是 set 模型**單獨**的分數，不是融合後的；prereg19 的經驗是融合後的增益和單獨的增益同量級（SET 單獨 0.7286 對 Q09 0.7114 是 +0.017，融合 +0.023）。

**P 軸只記錄、不決定**：照交辦的寫法也算出 P 規則（S(P100) − S(P50) ≥ 0.004 且 S(P25) < S(P50) < S(P100)）成不成立，寫進報告，但**不影響 GO／NO-GO**：P 軸量的是「更多玩家」的價值，而 extra 沒有任何新玩家；若 P 軸進步、R 軸不進步，加 extra 不會有用，GO 是錯的；反之亦然。

- 判定完照實寫；不因為接近門檻而改規則或加種子。

### 4.2 S24 和用法

- 特徵：P1＋P2＋P3＋P4 一起用 `tools/p09_map.build_prep` 的同一套組裝寫到 `data/prereg24/prep/`；接縫：前 270,000 列 `probe_X` 和 `inner_X` 和現行的逐位元組相同。
- **S24**：S19 的架構和全部設定（步數、batch、種子 0／1／2、抽題、選步）一字不改，A 換成「S19 的 A 玩家的 probe＋P4 盤」，H 和留出題組照 S19。也就是說，S24 和 S19 只差訓練資料。
- **用法：S24 取代 SET（Q24＝Q09＋SET24，7 項，SET24 放在 SET 的位置）**，不加第 8 項。理由：prereg23 的 SET2 和 S19 高度重疊——「加一項」和「取代」幾乎一樣（0.7411 對 0.7410），而且融合在 3／5 折把 w_SET 擬合成 0；S24 是同一個架構在 S19 的資料的超集合上訓練，和 S19 重疊只會更多。加一項只多一個要擬合、在折之間不穩的權重，沒有預期的好處。
- 融合參數照 19 的方式：inner 5 折 OOF 評估；採用時用全部 inner 擬合假題重擬合 7 項（`p4.gen_fit_record`）。
