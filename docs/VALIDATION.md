## 怎麼切

- **以玩家為單位切**：一位玩家只屬於一個等級，按盤隨機切的話，模型可以靠「認出這個人」猜中等級，理由見 `docs/DATA.md`。
- **分層**：每個「等級 × 每人盤數分箱」（1–4、5–24、25–104、105 盤以上）是一層。層內用 `sha256("c10-split-v1|split|player_id")` 排序，前 `int(0.2·n+0.5)` 人歸驗證集。
- **結果**：驗證集 1,600 人、206,137 盤；訓練集 6,407 人、793,863 盤。清單在 `results/split_v1/players_split.csv`。
  - 驗證集裡有 11 人不到 5 盤（共 39 盤），不出題，也不能拿來訓練。
- **內部驗證（rev 2）**：選 checkpoint、選超參數時用內部驗證。
  - 做法：在訓練玩家內照同樣的分層，改用 `sha256("c10-split-v1|inner|player_id")` 排序，每層取前 `int(0.1·n+0.5)` 人，共 640 人、73,556 盤。
  - 其餘 5,767 人、720,307 盤用來訓練。
  - 內部驗證和本機驗證集的交集是 0，程式會檢查。
- **驗證玩家的棋一律不能拿來訓練**，包括調超參數、選 checkpoint、做特徵統計。
  - **rev 2 起**，所有訓練程式（本機或 Colab）都要透過 `tools/c10data.py` 的 `load_rows()` 讀資料。它只回傳訓練玩家的棋、核對人數和盤數，並確認回傳的每一盤都不在 `data/local/` 的驗證檔裡。
  - 例外：有些方法會在測試時利用題目檔和候選庫（不含答案），例如用候選庫微調。官方測試時同樣拿得到這些東西，所以本機可以用驗證題目檔和候選庫做同樣的事，但要寫進事前登記。

## 驗證題

驗證題放在 `data/local/`，裡面有棋譜內容，所以不進 git。重建指令：

```
python tools/make_val.py data/training data/local results/split_v1
```

重跑後每個檔案的 SHA-256 要和 manifest 一樣（Python 3.10、3.12、3.14 都實測過）。

| | 競賽二（棋力） | 競賽一（辨識玩家） |
|---|---|---|
| 題目 | `rank_val_questions.csv`，1,589 題 | `player_val_questions.csv`，400 題 |
| 出題方式 | 每位驗證玩家（≥5 盤）出一題。先從 5–20 均勻抽出盤數 k，k 超過玩家盤數時取該玩家全部的棋 | 候選庫 400 人 × 100 盤（`player_val_candidates.csv`），每人再從候選以外的棋抽 5–20 盤當一題 |
| 答案 | `rank_val_answers.csv` | `player_val_answers.csv` |
| 各級題數 | D 178、C 163、B 207、A 308、1D 87、2D 122、3D 124、4D 128、5D 131、6D 141 | 從 539 位符合條件的驗證玩家（≥105 盤）選出 400 人，跨等級，每級 32–48 人 |
| 每題盤數 | 平均 12.06 盤，其中 311 題因玩家盤數不夠而被截斷。各級平均：A 10.96、D 11.83、5D 11.99、C 12.14、B 12.16、1D 12.24、3D 12.38、2D 12.79、4D 12.79、6D 12.85 | 5–20 |
| 其他 | 格式和官方測試檔相同，推論程式可以直接共用 | 候選玩家代號改成 `val_p_` 加雜湊。**本機是一題對一人**，官方未必如此 |

- **競賽一推論（rev 2）**：候選清單一律照玩家代號排序，不能依賴檔案的列順序。
- **不能當特徵**：`num_games` 帶一點等級訊號（A 級題目的盤數比較少），模型不能把它當特徵。
- **一對一結構**：利用「一題對一人」的方法（例如 Hungarian 指派）要另寫事前登記，並註明官方未必成立。

## 計分與比較

評分程式是 `tools/score.py`，照官方公式計分。

- **測試**：`tests/` 有 22 個測試，包括手算的計分、bootstrap 區間、打分紀錄帳、嚴格格式檢查、讀資料的外洩檢查。另外故意把程式改錯 10 種，10 種都會讓測試失敗。
- **獨立比對**：稽核代理用自己寫的計分程式比對，小數點後 12 位一致。

### 競賽二主要指標：分等級平均

`rank_balanced_mean`：先算每級平均，再取 10 級的平均。

- **為什麼**：驗證集裡 A 級的題目最多（308 題），1D 最少（87 題）。每題等權的話，全部猜 A 就有 0.262；分等級平均下，全部猜同一級最多只有 0.174。模型的訓練棋各級大致平均（最多是最少的 1.067 倍）。
- **風險（rev 2）**：
  - 官方分數是每題等權平均。只有官方各級題數相同時，分等級平均才會接近官方分數，這一點目前沒有證據。
  - 在分等級平均下，一題 1D 的權重是一題 A 的 3.54 倍。
  - 各級分數的差異有一部分來自每題盤數，不全是棋力，所以報告時要和各級平均盤數一起列。
  - 11/04 後，用模型對測試題的預測分布檢查官方的各級題數。
- **次要指標**：每題等權平均（`mean`）。兩個都報告。
- **兩個指標結論相反時（rev 2）**：一個的 CI 下界 > 0，另一個的點估計 < 0，就**不採用**新方法，並記為「結論依指標而定」。

### 比較兩個方法

`python tools/score.py compare-rank A.csv B.csv 答案.csv --ledger results/score_ledger.csv --note "..."`，報告的差值是 B−A。

- 做法是配對 bootstrap：1 題＝1 位玩家，重抽 10,000 次，seed 0。主要指標在每個等級內分層重抽。
- **採用條件**：主要指標差值的 95% 信賴區間下界 > 0。

## 紀律

照 `competitions/CLAUDE.md` 的規定：

1. **先登記再跑**：新方法先寫事前登記（`docs/PREREG_*.md`）：要比什麼、怎樣算成功。寫完 commit 才開始跑。
2. **驗證集只打一次分**：每個凍結的方法，在驗證集上只打一次分。選超參數、選 checkpoint 用內部驗證，不用驗證集。
3. **不動手改答案**：驗證題不逐題手調，測試集預測不人工修改。
4. **看過官方分數的選擇要寫明**：看了官方排行榜分數才做的選擇，報告裡要寫明。
   - **最後一次上傳交哪一版（rev 2）**：只依本機驗證集的主要指標和事前登記的採用條件決定。
   - public 分數只用來抓格式錯誤和大幅退步：比上一版低 0.05 以上才追查。官方 public 只有 400 題，標準誤最多 0.025，差距小於 0.05 不能當成方法好壞的證據。
   - 每次上傳都記進 `results/official_scores.json`：日期、版本 commit、public 分數、上傳理由。
   - 上傳前一定要跑 `tools/check_submission.py`，通過才上傳。
5. **本機驗證和官方排行榜不一定一致**：
   - 可能的原因：官方測試玩家可能在訓練集裡、官方候選庫可能不跨等級、每題盤數的分布可能不同、官方可能不是一題對一人、同一人可能出多題。
   - 11/04 拿到測試集後，照 `docs/DATA.md` 最後一節逐項檢查，再決定要不要開 split v2。
6. **打分紀錄帳（rev 2）**：
   - 每次用 `data/local/*_answers.csv` 打分，都在 `results/score_ledger.csv` 加一列。地板分數、查 bug 重跑、失敗的跑都算。
   - `score.py` 在沒有 `--ledger` 和 `--note` 時，拒絕用驗證答案打分。
   - 這個檔只增不刪，和結果一起 commit。**帳上沒有的分數不得引用。**
7. **答案檔不上傳 Colab（rev 2）**：Colab 只放題目檔和候選庫，打分只在本機做。
8. **只有指定的 checkpoint 可以打分（rev 2）**：只有事前登記指定的 checkpoint 可以在驗證集打分，其他 `epoch_*.pth` 一律不打分。
